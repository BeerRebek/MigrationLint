# MIG011 — Destructive raw SQL

| | |
|---|---|
| **Category** | dataloss |
| **Default severity** | warning |
| **Triggers on** | `Sql(...)` containing a destructive statement |

Matched (case-insensitive, word-boundary):

- `DROP TABLE|COLUMN|INDEX|CONSTRAINT|SCHEMA`
- `TRUNCATE`
- `DELETE FROM` with no `WHERE` in the same statement
- `UPDATE` with no `WHERE` in the same statement

## Why this matters

Raw SQL bypasses every other check in this tool — MigrationLint cannot model its effect the way
it models `AddColumn` or `CreateIndex`. A destructive statement hidden in `Sql()` is exactly the
kind of change that most needs a second look.

## Bad

```csharp
migrationBuilder.Sql("TRUNCATE TABLE \"AuditLogs\";");
migrationBuilder.Sql("UPDATE \"Orders\" SET \"Status\" = 'closed';"); // no WHERE
```

## Safe

1. Confirm the statement is scoped (a `WHERE` clause where applicable).
2. Test against a production-sized copy.
3. If intentional, suppress with a justification so reviewers see the intent.

## Not implemented

SQL-injection detection on interpolated strings is deliberately **not** done — migrations do not
take user input, so that check produces noise without a matching threat.

## Suppressing

```csharp
[SuppressMigrationLint("AuditLogs is a scratch table rebuilt on every deploy.", "MIG011")]
```
