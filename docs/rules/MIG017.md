# MIG017 — CONCURRENTLY index without SuppressTransaction

| | |
|---|---|
| **Category** | failure |
| **Default severity** | error |
| **Scope** | migration-level |
| **Triggers on** | a `CreateIndex` annotated `Npgsql:CreatedConcurrently` when the migration does not override `SuppressTransaction` |

## Why this matters

`CREATE INDEX CONCURRENTLY` **cannot run inside a transaction**. EF Core wraps each migration in a
transaction by default, so an index marked `CreatedConcurrently` will **fail at runtime** unless the
migration opts out of the transaction. This is the mistake people make right after adopting MIG007.

## Bad

```csharp
public partial class AddOrderNotesIndex : Migration
{
    // ❌ no SuppressTransaction override
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.CreateIndex(name: "IX_Orders_Notes", table: "Orders", column: "Notes")
            .Annotation("Npgsql:CreatedConcurrently", true);
    }
}
```

## Good

```csharp
public partial class AddOrderNotesIndex : Migration
{
    protected override bool SuppressTransaction => true;

    protected override void Up(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.CreateIndex(name: "IX_Orders_Notes", table: "Orders", column: "Notes")
            .Annotation("Npgsql:CreatedConcurrently", true);
    }
}
```

Keep the concurrent index as the **only** operation in the migration.
