# MIG002 — Table dropped

| | |
|---|---|
| **Category** | dataloss |
| **Default severity** | error |
| **Triggers on** | `DropTable` |
| **Skipped when** | the table was created in this migration |

## Why this matters

Dropping a table is irreversible and destroys all of its data. It also breaks any app version,
report, or integration still referencing it.

## Bad

```csharp
migrationBuilder.DropTable(name: "Invoices");
```

## Safe

1. Confirm no application code or report references the table.
2. Take an explicit backup or export of the data.
3. Rename the table (e.g. `Invoices_deprecated_20260809`) in one release.
4. Drop it in a later release after a soak period.

## Suppressing

```csharp
[SuppressMigrationLint("Table exported to cold storage and unreferenced since v2.", "MIG002")]
```
