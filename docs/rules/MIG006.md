# MIG006 — Nullable column made NOT NULL

| | |
|---|---|
| **Category** | failure |
| **Default severity** | error |
| **Triggers on** | `AlterColumn` where `oldNullable: true` and `nullable: false` |
| **Skipped when** | the column is on a table created in this migration |

## Why this matters

Setting a nullable column to `NOT NULL` fails if any existing row holds `NULL`. As with MIG004,
this passes locally and fails against real data.

## Bad

```csharp
migrationBuilder.AlterColumn<string>(
    name: "Status", table: "Orders", nullable: false,
    oldClrType: typeof(string), oldNullable: true);
```

## Safe

1. Backfill NULLs in a prior deployment.
2. Verify: `SELECT COUNT(*) FROM "Orders" WHERE "Status" IS NULL;`
3. Apply the `NOT NULL` change once the count is zero.

**PostgreSQL** — add a `CHECK (col IS NOT NULL)` constraint as `NOT VALID` first, validate it
without blocking writes, then set `NOT NULL`.

## Suppressing

```csharp
[SuppressMigrationLint("Status backfilled to 'pending' in the previous release.", "MIG006")]
```
