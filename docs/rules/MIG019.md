# MIG019 — Stored computed column added (forces a table rewrite)

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AddColumn`/`AlterColumn` with `computedColumnSql` and `stored: true` |
| **Skipped when** | new table; small table; virtual (non-stored) computed columns |

## Why this matters

A **stored** (persisted) computed column has its value calculated and physically written for every
existing row when it's added — a full table rewrite under a lock. A **virtual** computed column is
metadata-only and is *not* flagged.

## Bad

```csharp
migrationBuilder.AddColumn<string>(
    name: "FullName", table: "Customers", nullable: true,
    computedColumnSql: "\"First\" || ' ' || \"Last\"", stored: true);
```

## Safe

1. Add it as a **virtual** computed column if your reads allow it (`stored: false`), or
2. Add a plain column, backfill the computed value in batches, then switch reads.

## Suppressing

```csharp
[SuppressMigrationLint("Customers is small; the rewrite is cheap.", "MIG019")]
```
