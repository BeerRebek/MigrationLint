# MIG008 — Unique constraint or unique index added

| | |
|---|---|
| **Category** | locking |
| **Default severity** | error |
| **Triggers on** | `AddUniqueConstraint`, or `CreateIndex` with `unique: true` |
| **Skipped when** | new table; small table |

## Why this matters

Adding a unique constraint scans the entire table under lock to prove uniqueness, and it fails
outright if duplicate values already exist. On a large table that is both a write outage and a
migration that can abort mid-deploy.

## Bad

```csharp
migrationBuilder.CreateIndex(name: "IX_Users_Email", table: "Users", column: "Email", unique: true);
```

## Safe

1. Check for duplicates first:
   ```sql
   SELECT Email, COUNT(*) FROM "Users" GROUP BY Email HAVING COUNT(*) > 1;
   ```
2. Resolve any duplicates.
3. **PostgreSQL** — build the unique index concurrently, then attach it:
   ```sql
   CREATE UNIQUE INDEX CONCURRENTLY ix ON "Users" (Email);
   ALTER TABLE "Users" ADD CONSTRAINT c UNIQUE USING INDEX ix;
   ```

## Suppressing

```csharp
[SuppressMigrationLint("Users is a small tenant table; scan is trivial and duplicates impossible.", "MIG008")]
```
