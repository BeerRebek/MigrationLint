# MIG014 — Primary key added to an existing table

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AddPrimaryKey` |
| **Skipped when** | new table; small table |

## Why this matters

Adding a primary key to a table that already has data is not free:

- **PostgreSQL** builds a unique index and sets the columns `NOT NULL` under an `ACCESS EXCLUSIVE`
  lock — it scans the whole table and blocks reads and writes.
- **SQL Server** rewrites and reorders the entire table for a *clustered* primary key.

It also fails outright if the columns contain duplicates or NULLs.

## Safe — PostgreSQL

```sql
CREATE UNIQUE INDEX CONCURRENTLY pk_ix ON "Orders" ("Id");
ALTER TABLE "Orders" ADD CONSTRAINT "PK_Orders" PRIMARY KEY USING INDEX pk_ix;
```

## Safe — SQL Server

Prefer a **nonclustered** primary key (no table rewrite), or schedule the clustered rebuild in a
maintenance window.

## Suppressing

```csharp
[SuppressMigrationLint("Table is a small lookup; the rebuild is trivial.", "MIG014")]
```
