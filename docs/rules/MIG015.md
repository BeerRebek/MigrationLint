# MIG015 — Integer type widened (forces a table rewrite)

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AlterColumn` where the CLR integer type widens (`byte`→`short`→`int`→`long`) |
| **Skipped when** | new table; small table |

## Why this matters

Widening an integer column — the classic **`int` → `bigint`** when a table outgrows 32-bit ids —
is not data loss, but it *does* change the column's on-disk size. The engine rewrites **every row**
under a lock to do it. On a large, hot table that is a long outage.

(Narrowing a type is a different problem — that's [MIG005](MIG005.md).)

## Bad

```csharp
migrationBuilder.AlterColumn<long>(
    name: "Id", table: "Orders", nullable: false,
    oldClrType: typeof(int));
```

## Safe

1. Add a new column with the wider type.
2. Backfill in batches (a background job, not this migration) and dual-write from the app.
3. Switch reads to the new column, then drop the old one in a later release.

## Suppressing

```csharp
[SuppressMigrationLint("Orders is small; the rewrite completes quickly.", "MIG015")]
```
