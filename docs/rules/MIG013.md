# MIG013 — Check constraint added without deferred validation

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AddCheckConstraint` when provider is PostgreSQL or SQL Server |
| **Skipped when** | new table; small table; MySQL / SQLite / unknown provider |

## Why this matters

Like a foreign key, adding a `CHECK` constraint the default way validates **every existing row**
while holding a lock on the table. On a large table that blocks writes for the duration.

## Safe — PostgreSQL

```csharp
migrationBuilder.Sql("ALTER TABLE \"Orders\" ADD CONSTRAINT \"CK_Orders_Total\" CHECK (\"Total\" >= 0) NOT VALID;");
// later migration:
migrationBuilder.Sql("ALTER TABLE \"Orders\" VALIDATE CONSTRAINT \"CK_Orders_Total\";");
```

## Safe — SQL Server

```csharp
migrationBuilder.Sql("ALTER TABLE [Orders] WITH NOCHECK ADD CONSTRAINT [CK_Orders_Total] CHECK ([Total] >= 0);");
// later migration:
migrationBuilder.Sql("ALTER TABLE [Orders] WITH CHECK CHECK CONSTRAINT [CK_Orders_Total];");
```

## Suppressing

```csharp
[SuppressMigrationLint("Orders is small; the validation scan is instant.", "MIG013")]
```
