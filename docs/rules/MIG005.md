# MIG005 — Column type narrowed

| | |
|---|---|
| **Category** | dataloss |
| **Default severity** | error |
| **Triggers on** | `AlterColumn` |
| **Skipped when** | the column is on a table created in this migration; old/new values are not both known |

## Why this matters

Narrowing a column truncates or rejects existing values, and most engines rewrite the entire
table under lock to change the storage type. A single rule covers all three narrowing shapes
(the competitor splits these across three overlapping analyzers):

- `maxLength` decreased (e.g. `varchar(200)` → `varchar(50)`)
- CLR numeric rank decreased (`byte`=1, `short`=2, `int`=3, `long`=4, `decimal`=5)
- `precision` or `scale` decreased

## Bad

```csharp
migrationBuilder.AlterColumn<string>(
    name: "Code", table: "Products", maxLength: 50,
    oldClrType: typeof(string), oldMaxLength: 200);
```

## Safe

1. Verify no existing value exceeds the new bound.
2. Add a new column with the target type.
3. Dual-write from the application, then backfill.
4. Switch reads to the new column, then drop the old one in a later release.

## Suppressing

```csharp
[SuppressMigrationLint("Verified max(len(Code)) = 12 in production; safe to shrink.", "MIG005")]
```
