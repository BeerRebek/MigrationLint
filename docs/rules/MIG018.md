# MIG018 — Migration checked in without a ModelSnapshot update

| | |
|---|---|
| **Category** | hygiene |
| **Default severity** | warning |
| **Scope** | corpus-level (whole migrations folder) |
| **Triggers on** | the newest migration's `BuildTargetModel` not matching `ModelSnapshot`'s `BuildModel` |

## Why this matters

EF Core keeps two copies of your model in sync: the `*ModelSnapshot.cs` (the current model) and each
migration's `BuildTargetModel` (the model *after* that migration, in its `.Designer.cs`). For the
**newest** migration, these must be identical.

When they diverge, the snapshot is stale — almost always because a migration was merged without its
snapshot change (a classic merge-conflict resolution bug). The damage is delayed: the **next**
migration you generate is computed against the wrong baseline, so it emits wrong or duplicate
operations.

MigrationLint compares the two (ignoring whitespace and `ProductVersion`) and flags the drift. It
never fires when a file is missing, so there are no false positives from an unusual layout.

## Fix

1. Resolve the merge so the `ModelSnapshot` reflects **every** applied migration, **or**
2. Remove the conflicting migration and re-run `dotnet ef migrations add`.

Verify with:

```bash
dotnet ef migrations has-pending-model-changes
```

## Suppressing

Set it off in config if your snapshot is intentionally managed elsewhere:

```json
{ "rules": { "MIG018": "off" } }
```
