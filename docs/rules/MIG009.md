# MIG009 — Foreign key added without NOT VALID (PostgreSQL)

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AddForeignKey` when provider is PostgreSQL |
| **Skipped when** | new table; small table; non-PostgreSQL provider |

## Why this matters

By default PostgreSQL validates every existing row when a foreign key is added, holding a lock on
**both** the referencing and referenced tables for the duration of the scan. On large tables that
blocks writes long enough to matter.

`NOT VALID` lets you add the constraint instantly (new rows are checked immediately) and validate
the existing rows separately, without blocking writes.

## Bad

```csharp
migrationBuilder.AddForeignKey(
    name: "FK_Orders_Customers_CustomerId",
    table: "Orders", column: "CustomerId",
    principalTable: "Customers", principalColumn: "Id");
```

## Safe — split into two migrations

```csharp
// Migration 1 — fast, no scan:
migrationBuilder.Sql(
    "ALTER TABLE \"Orders\" ADD CONSTRAINT \"FK_Orders_Customers_CustomerId\" " +
    "FOREIGN KEY (\"CustomerId\") REFERENCES \"Customers\" (\"Id\") NOT VALID;");

// Migration 2 — validates without blocking writes:
migrationBuilder.Sql(
    "ALTER TABLE \"Orders\" VALIDATE CONSTRAINT \"FK_Orders_Customers_CustomerId\";");
```

## Suppressing

```csharp
[SuppressMigrationLint("Orders is small; the validation scan completes instantly.", "MIG009")]
```
