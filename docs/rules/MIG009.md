# MIG009 — Foreign key added without deferred validation

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `AddForeignKey` when provider is PostgreSQL or SQL Server |
| **Skipped when** | new table; small table; MySQL / SQLite / unknown provider |

## Why this matters

By default the database validates every existing row when a foreign key is added, holding a lock
that blocks writes for the duration of the scan. On large tables that is long enough to matter.
Both PostgreSQL and SQL Server let you add the constraint instantly and validate separately.

## Bad

```csharp
migrationBuilder.AddForeignKey(
    name: "FK_Orders_Customers_CustomerId",
    table: "Orders", column: "CustomerId",
    principalTable: "Customers", principalColumn: "Id");
```

## Safe — PostgreSQL (`NOT VALID`)

```csharp
// Migration 1 — fast, no scan:
migrationBuilder.Sql(
    "ALTER TABLE \"Orders\" ADD CONSTRAINT \"FK_Orders_Customers_CustomerId\" " +
    "FOREIGN KEY (\"CustomerId\") REFERENCES \"Customers\" (\"Id\") NOT VALID;");

// Migration 2 — validates without blocking writes:
migrationBuilder.Sql(
    "ALTER TABLE \"Orders\" VALIDATE CONSTRAINT \"FK_Orders_Customers_CustomerId\";");
```

## Safe — SQL Server (`WITH NOCHECK`)

```csharp
// Migration 1 — fast, no scan (holds only a brief schema lock):
migrationBuilder.Sql(
    "ALTER TABLE [Orders] WITH NOCHECK ADD CONSTRAINT [FK_Orders_Customers_CustomerId] " +
    "FOREIGN KEY ([CustomerId]) REFERENCES [Customers] ([Id]);");

// Migration 2 — validates and marks the constraint 'trusted' without blocking writes:
migrationBuilder.Sql(
    "ALTER TABLE [Orders] WITH CHECK CHECK CONSTRAINT [FK_Orders_Customers_CustomerId];");
```

A `NOCHECK` constraint is *not trusted* by the query optimizer until step 2 runs, so don't skip it.

## Suppressing

```csharp
[SuppressMigrationLint("Orders is small; the validation scan completes instantly.", "MIG009")]
```
