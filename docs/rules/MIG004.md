# MIG004 — NOT NULL column added without a default

| | |
|---|---|
| **Category** | failure |
| **Default severity** | error |
| **Triggers on** | `AddColumn` where `nullable: false` and no `defaultValue`/`defaultValueSql` |
| **Skipped when** | the column is on a table created in this migration; nullability is not a literal |

## Why this matters

Adding a `NOT NULL` column with no default to a table that already has rows fails immediately —
the database cannot populate the new column for existing rows. It passes on an empty local
database and fails the moment it hits real data.

## Bad

```csharp
migrationBuilder.AddColumn<string>(name: "Notes", table: "Orders", nullable: false);
```

## Safe

**Option A — supply a default (single deployment):**

```csharp
migrationBuilder.AddColumn<string>(
    name: "Notes", table: "Orders",
    nullable: false, defaultValue: "");
```

**Option B — three-step, when a default is not acceptable:**

1. Add the column as nullable.
2. Backfill existing rows in batches (a background job, not this migration).
3. Once no NULLs remain, alter the column to `NOT NULL`.

## Suppressing

```csharp
[SuppressMigrationLint("Orders table is guaranteed empty at this point in the rollout.", "MIG004")]
```
