# MIG020 — Index dropped without CONCURRENTLY (PostgreSQL)

| | |
|---|---|
| **Category** | locking |
| **Default severity** | warning |
| **Triggers on** | `DropIndex` when provider is PostgreSQL |
| **Skipped when** | new table; small table; non-PostgreSQL provider |

## Why this matters

A plain `DROP INDEX` on PostgreSQL takes an `ACCESS EXCLUSIVE` lock on the table — it briefly blocks
**all reads and writes** while it runs. `DROP INDEX CONCURRENTLY` avoids the blocking lock.

## Bad

```csharp
migrationBuilder.DropIndex(name: "IX_Orders_Legacy", table: "Orders");
```

## Safe

`DROP INDEX CONCURRENTLY` can't run inside a transaction, so drop it via raw SQL in a
transaction-less migration:

```csharp
protected override bool SuppressTransaction => true;

protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.Sql("DROP INDEX CONCURRENTLY \"IX_Orders_Legacy\";");
}
```

## Suppressing

```csharp
[SuppressMigrationLint("Small table; the brief lock is acceptable.", "MIG020")]
```
